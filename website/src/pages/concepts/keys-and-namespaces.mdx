# Keys and namespaces

## Keys

A key is any string, but gocache does not hand it to the driver unchanged. Every stored key carries
a mandatory prefix naming the library, the key-format version, and which kind of thing is being
stored:

```
gocache:1:d:<namespace...>:<key>    data entries
gocache:1:t:<tag>                   tag markers
gocache:1:l:<namespace...>:<name>   locks
```

The leading `gocache` is configurable with [`WithKeyPrefix`](/reference/options); the `1` is the
version of this layout. Namespace segments appear only when you are working inside a namespace.

**Segments are escaped, which makes the encoding unambiguous.** Every variable part — each
namespace name, the key, the tag, the lock name, and the configured prefix — has `\` rewritten as
`\\` and `:` as `\:` before the parts are joined with `:`. A colon in a key stays fine and idiomatic
(`user:42:preferences`) and can no longer be mistaken for a namespace boundary:

```go
gocache.Set(ctx, cache.Namespace("a"), "b:c", value)   // gocache:1:d:a:b\:c
gocache.Set(ctx, cache.Namespace("a:b"), "c", value)   // gocache:1:d:a\:b:c
```

Those were the same underlying string before the escaping existed. They are now distinct entries,
and one cannot be read or cleared through the other.

**No key name is reserved.** Tag markers and locks live in their own domains (`:t:` and `:l:`), not
in the data domain your keys land in, so an application key literally called `__gocache:tag:users`
is just an ordinary entry. It cannot suppress a tag invalidation, and an application `Delete` cannot
free somebody's lock.

**Keys are still not validated.** Escaping makes the encoding unambiguous; it does not sanitise. If
you build keys from user input, bound its length and content yourself — some drivers cap key size
(the MySQL schema at 255 bytes, for instance).

A convention that ages well is `entity:id:aspect`:

```go
"user:42"
"user:42:permissions"
"article:1138:rendered"
```

## Namespaces

`Namespace` returns a derived cache that prefixes every key it touches:

```go
users := cache.Namespace("users")

err := gocache.Set(ctx, users, "42", user)   // stored as "gocache:1:d:users:42"
value, found, err := gocache.Get[User](ctx, users, "42")
```

They nest, appending a segment as they go:

```go
cache.Namespace("users").Namespace("permissions")   // gocache:1:d:users:permissions:...
```

### What namespaces are for

**Keeping subsystems apart.** Two teams both caching under `settings` will not collide if each works
inside its own namespace.

**Bounded clearing.** `Clear` removes only data-domain keys under the namespace you call it on:

```go
err := cache.Namespace("users").Clear(ctx)   // clears "gocache:1:d:users:*"
err = cache.Clear(ctx)                       // clears "gocache:1:d:*"
```

:::note[What a root Clear reaches]
A root `Clear` removes every data entry this cache wrote, including entries written through every
namespace derived from it — and nothing else. It cannot touch keys that do not carry gocache's
prefix, so sharing one Redis logical database with sessions, queues or rate limiters is safe.

Tag markers and locks live in their own domains and survive a `Clear`. Clearing a cache does not
release a lock another process is holding, and does not discard tag invalidation history — a
deliberate choice, since neither is cache data.

Two caches over the same store configured with different [`WithKeyPrefix`](/reference/options)
values are likewise invisible to each other's reads and clears.
:::

Namespacing still earns its keep for reasons other than blast radius: it keeps subsystems from
colliding, and it lets you clear one subsystem's data without discarding the rest.

### What namespaces share

A namespace is a view, not a separate cache. It shares the parent's drivers, bus, options — and its
lifecycle:

```go
users := cache.Namespace("users")
defer users.Close()   // closes the root cache and every other namespace
```

`Close` on a namespace closes the underlying cache. If a helper function takes a namespace and
defers `Close` on it, it will shut down caching for the entire application. Close the root, once.

### Namespaces and tags

Tags are global. A tag marker is stored at `gocache:1:t:<tag>`, outside any namespace, so one tag
can span several namespaces:

```go
err := gocache.Set(ctx, cache.Namespace("users"), "42", user, gocache.WithTags("tenant:7"))
err = gocache.Set(ctx, cache.Namespace("orders"), "99", order, gocache.WithTags("tenant:7"))

err = cache.DeleteByTag(ctx, "tenant:7")   // invalidates both
```

That is deliberate: tags exist to express relationships that cut across the storage layout. See
[Tags](/features/tags).

Lock names, by contrast, *are* namespaced — `cache.Namespace("users").Lock("rebuild", ttl)` acquires
`gocache:1:l:users:rebuild`, a different lock than `cache.Lock("rebuild", ttl)`.
